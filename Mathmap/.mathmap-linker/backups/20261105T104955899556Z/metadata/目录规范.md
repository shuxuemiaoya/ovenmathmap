# Mathmap 六目录设计

状态：六目录已投入使用，按明确授权逐来源导入。import_book_graph.py 已实现经过审核的原生教材导入；旧版多来源原型使用另一套结构，不能混用。

## 六个内容目录

| 目录 | 层级 | 存放内容 | 子目录 |
| --- | --- | --- | --- |
| `习题` | 原子层 | 一道完整习题或例题的题干、来源与解析链接 | 题目平铺；解析平铺于 `解析/`；图片为技术子目录 |
| `题型` | 习题组织层 | 题型体系、题组、试卷、课后练习、教师选题与训练路径 | 保留体系、版本和原有层级 |
| `知识点` | 原子层 | 可复用的概念、定义、性质、定理、公式、方法与完整讲解 | 笔记平铺；允许 `attachments/` 技术子目录 |
| `知识串联` | 知识组织层 | 教材章节、知识结构、先修关系、教师讲授路线、专题知识体系 | 保留体系、版本和原有层级 |
| `问题袋` | 原子层 | 有趣问题、情景导入、探究情境、引出知识的思考与开放问题 | 笔记平铺；允许 `attachments/` 技术子目录 |
| `问题归类` | 问题组织层 | 问题专题、情境分类、探究路线、教师问题链 | 保留体系、版本和原有层级 |

`题型` 在本设计中是**习题的组织层**，不局限于按题名识别的语义题型。同一概念或题型出现在多个组织体系里是合理复用；不同来源的组织文件不能因名称相似或子项重合被自动合并。

## 原子平铺与身份

- 原子目录不按教材、章节或老师分子文件夹。一本教材和一位老师可以同时使用同一个原子，归属通过组织文件的链接表达。
- “平铺”指原子 Markdown 在各自容器中平铺：`习题/`、`习题/解析/`、`知识点/`、`问题袋/`。它不禁止解析类型分区和图片技术目录。
- 原子身份由稳定 ID 决定，显示标题、文件名、来源路径可以变化。习题优先保留已确认的 QID；知识用 KID，情境问题用 PID。不同来源的同一原子拥有多条来源记录。
- 语义审核确认重复后，只保留一个共享入口，按来源保存完整表述、适用条件、推导和不同解析。名称相似只是候选信号；文字、数值、条件或符号不同的习题不能直接合并。
- 用有意义的标题加稳定 ID 处理重名；标题中必要的数学上下文不能被去重清洗删除，例如椭圆与双曲线的“离心率”。
- “习题”与“问题袋”按教学用途区分，不按难度区分。正式练习、例题和考核题进入习题；动机情境、探究和开放问题进入问题袋。同一内容承担不同用途时，复用一个原子并记录来源角色，不机械复制两份。

原子平铺是物理存储规则，日常浏览以组织目录和搜索为入口。大规模习题不要依靠一个包含全部原子的巨大目录页导航；用各套组织体系、标签与来源索引检索。性能索引可放隐藏状态目录，不能为了归档方便把同一原子按教材复制成多份。

## 组织体系与混合章节

- 三个组织目录都允许不限深度的子目录。每套教材、每个版本、每位老师的体系独立保留；同一老师可以拥有多套不同用途的体系。
- 组织体系使用独立 `system_id`，记录来源、版本、组织者、原章节路径及顺序。体系 ID 不依赖显示名，以便老师改名或教材重排。
- 一个来源的混合章节可以产生知识、习题和情境问题三个组织视图。它们共享来源章节身份，分别保持相关子项的原始顺序，并显式互链；原子内容不复制进多个组织文件。
- 组织笔记负责顺序、归属和导航，允许跨层引用。不要为了三类视图创建没有内容的占位层级；没有某类子项的章节不生成该视图。
- 组织页默认链接与摘要，不递归展开整本书或全部习题/解析。保留来源的子项顺序；需要展示时只嵌入有限原子，以控制 Obsidian 和网页的单页读取量。
- 混合来源中尚未原子化的完整讲解或情境不能静默丢掉，也不能仅用正则强行切碎。实际导入前应审阅其边界与归属，再形成原子和组织视图。

## 原子之间的学习关系

```text
先修知识 ──→ 当前知识点 ──→ 后续知识
                  ↑              
问题袋中的情境 ───┤
推导/证明依据 ────┘
                  │
                  ├──→ 题型/训练组织 ──→ 习题
                  └──→ 对应习题与例题
```

知识点页应能打开先修知识、引入问题、推导依据、后续知识、相关题型和习题，以及使用它的知识串联。习题页能返回对应知识点、相关情境和所属题型/试卷；问题袋中的原子能前往它引出的知识和使用它的问题链。

题目与解析分文件存放，题目链接对应的全部解析，解析以普通返回链接关联题目。每份解析保留独立身份、解法、来源和图片；同一题目可以有多个来源或多种解法。沿用已确认的解析 ID，新解析的 ID 不因列表排序而变化。完全相同的解析可在审核后复用并保留全部出处。来自上游完整例题的题干/解析分离需要审阅边界，不能仅凭“解”等字符串切分。双向关系不得构成互相嵌入的渲染循环。

组织归属、知识依赖和教学动机是不同关系。一个文件排在另一个前面，不足以建立先修关系。关系要保留证据和来源，正向链接与返回链接都显式呈现。来源未提供的关系标为待审阅或不适用，并说明原因。

## Agent 边界与验收

按明确授权整理选定来源，先审核身份、正文区间、组织顺序、图片和学习关系，再只读规划、验收和写入。不得把一本教材的导入扩大到整个高中目录。

每次导入需验证：原子笔记在四个容器内平铺；三类组织结构全部保留；题干与解析身份和双链完整；图片归属、来源和路径可解析；来源条目有完整去向；重复原子不丢来源差异；没有坏链接；关系缺口可追溯；手工修改受保护；重复运行不产生重复内容。清空或替换目标前还需限定路径、列出变更并留可恢复备份。

## 已确定的物理存储规则

1. 解析独立放在 `习题/解析/`，属于原子层。题目与解析通过稳定 ID 和双向链接关联。
2. 图片跟随所属原子容器：`习题/attachments/`、`习题/解析/attachments/`、`知识点/attachments/`、`问题袋/attachments/`。同一容器共享图片池，用完整内容哈希命名，并按前两位十六进制字符分桶。
3. 原图是可追溯的正式资产。网页缩略图和响应式派生图在发布产物或构建缓存中生成，不把多档尺寸堆进 Obsidian 的原子目录。

已导入来源及数量见索引和各教材的来源与整理说明。原图保留原始字节，网页派生图与 Obsidian 设置属于独立操作。
