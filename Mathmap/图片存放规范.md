# 原子图片归属与读取设计

本规范适用于 Mathmap 的五个原子图片池。教材导入负责原图归属、内容哈希分桶、链接重写和来源登记。图片压缩与网页派生图属于发布流程。

## 存放方式

图片归属五个原子容器，每个容器使用一个共享图片池：

```text
习题/attachments/<哈希前2位>/<完整SHA-256>.<扩展名>
习题/解析/attachments/<哈希前2位>/<完整SHA-256>.<扩展名>
知识点/attachments/<哈希前2位>/<完整SHA-256>.<扩展名>
问题袋/attachments/<哈希前2位>/<完整SHA-256>.<扩展名>
概念或公式/attachments/<哈希前2位>/<完整SHA-256>.<扩展名>
```

`00` 至 `ff` 的桶按需创建，不预建空目录。哈希根据图片实际字节计算，不使用文件名或原子 ID 代替。扩展名与实际媒体格式一致。同一图片的内容变化产生新地址；已有哈希地址中的内容不原地覆盖。

这是按原子类型归属的共享池，不是一题一个附件文件夹。原子与图片的对应关系由正文的明确路径和资产记录共同表达。记录图片 ID、实际路径、格式、字节数、宽高、使用它的原子 ID，以及各来源的原文件/页码/裁图范围。多个原子可引用同一个文件；“使用者”与“来源”都允许多条记录。

同一容器内完全相同的图片保存一份。跨容器保持各自的归属路径和可独立读取的普通文件，允许局部物理副本；全局图片 ID 仍使用同一内容哈希，供网页构建统一去重。不要为节省副本强制使用跨目录软链接或依赖原来源目录的路径。

原图保留来源字节和清晰度。数学符号、下标、细线和标注必须可辨认，不能因缩图或有损压缩丢失题目信息。来源本身是位图时，不凭空重绘为 SVG；来源本身是矢量图时保留其原始矢量资产。

## Markdown 与 Obsidian

图片用标准 Markdown 和相对当前笔记的完整路径，例如位于 `习题/` 的题目或位于 `习题/解析/` 的解析都可以写：

```markdown
![三角形及其辅助线](attachments/7a/7a…完整哈希….png)
```

目录树与上例中的省略号只用于展示，真实文件名必须是完整哈希。图片路径不依赖全库按 basename 猜测，也不使用机器绝对路径、临时目录地址或网页域名。网页构建器按当前笔记路径解析同一份 Markdown。

Obsidian 原生支持将新附件放入当前笔记目录下的指定子目录，可选择 `attachments`。此设置只解决附件落点，**不会自动计算哈希、分桶或建立资产索引**。手工粘贴的临时命名图片可先留在该目录；未来归档时必须检查引用、预览改名与链接更新，再进入哈希池。已有手工笔记不能被无差别改写。当前阶段只记录建议，不修改用户的 Obsidian 设置。

四类组织视图通过原子引用复用正文和图片，书章页通过链接串联这些视图。撤回来源时核对资产记录与实际引用，只有全部使用者随该来源移出的图片才可一并归档。共享图片继续由使用它的原子引用。

生成的组织页默认使用导航链接与必要摘要；确有展示需要时才嵌入有限的原子内容。不得把整本书、整套试卷或其多份解析递归嵌入同一个页面。题目默认链接独立解析，按需打开；折叠标题不应被当成 Obsidian 已经延后图片加载的保证。这样可以控制一次打开页面时实际需要读取和渲染的内容量。

## 网页端的加载策略

分桶提供可直接定位且规模可控的目录结构。它本身不保证页面读取更快；网页耗时需要分别检查传输量、解码、请求数和缓存。

- 构建时根据图片 ID 和明确路径生成页面所需的资产清单；页面请求不递归扫描图片目录、不加载全库图片索引。
- 原图保留不动。发布时按实际需要生成响应式派生图，默认宽度档为 480、960、1600 像素，只生成不超过原图宽度的档位；保留原图查看入口。它们是可重建发布产物，放在站点输出/构建缓存中。
- 对照片、扫描图尝试 WebP 等发布格式；对数学文字和线图以清晰度为门槛，优先原 SVG、PNG 或经核对的无损派生图。小公式不为凑尺寸档而放大。
- 页面用 `srcset` / `sizes` 按显示空间和屏幕像素密度选择图片，写入原始宽高以预留正确比例。首屏关键图片正常加载，屏幕外图片使用 `loading="lazy"`；题目折叠的解析应在展开/临近阅读时按需加载其内容与图片。
- 站点将五个本地池中的同一图片 ID 映射到统一发布资源。派生图缓存键包含原图哈希、转换配置和转换器版本，输出地址使用内容哈希；图片更新产生新地址，避免旧缓存误用。
- 对可缓存且内容不可变的图片资源设置较长的 `max-age` 与 `immutable`；是否允许共享缓存遵守站点访问策略。Markdown/页面数据采用单独的更新策略，不能照搬图片的长期不可变缓存。

这些网页措施不会自动改变 Obsidian 的加载行为。Obsidian 使用本地图片路径，归档阶段应避免反复重命名未变图片，并避免把站点多档缩略图加入 Vault 的索引负担。

## 后续实现的验收场景

1. 题目、解析、知识点、情境问题和概念或公式都能在 Obsidian 及网页预览中显示图片，路径中有中文也不损坏。
2. 同一池内两个原子共享一张图时不产生重复文件，来源与使用关系都保留；删除其中一个引用不能让另一原子丢图。
3. 原子标题或来源组织调整后，稳定图片 ID 不变。重新归类或移动原子时显式迁移/更新引用，不能依赖 basename 猜测。
4. 图片发生变化后生成新的资源地址；重复构建复用未变原图和派生图，不重复扫描或转换全库资产。
5. 多图页面使用合适尺寸，屏幕外图片延后请求，解析按需展开，图片出现时内容不明显跳动；数学标注经清晰度核对。
6. 以代表性页面分别记录图片传输字节、请求数、解码与渲染耗时、首屏表现、缓存命中情况；本设计不承诺未经测量的提速倍数。
