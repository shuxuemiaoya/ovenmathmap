# Mathmap 目录约束

遵守父目录的 Vault 数据完整性契约。

- 八个可见内容目录是：习题、题型、知识点、知识串联、问题袋、问题归类、概念或公式、公式总结。
- 原子笔记分别平铺在习题/、习题/解析/、知识点/、问题袋/、概念或公式/。解析是独立原子，题目与解析显式双向关联。
- 每个原子容器拥有自己的 `attachments/` 技术目录；正式图片按内容哈希命名并按前两位分桶，记录原子归属和来源。不预建空桶。
- 题型、知识串联与公式总结保留独立来源、版本和教师体系。问题归类按数学思想、方法策略与思维模型组织，不得用教材章节镜像代替；教材问题顺序另保存在知识串联的来源体系中。同一问题允许多个有依据的归属，均链接同一原子。
- 概念或公式是第四类原子，保存单个概念、定义或公式；公式总结是其组织层，保留独立来源与整理体系。知识点保留完整讲解，不按公式关键词自动拆分、迁移或复制既有笔记。新目录允许为空。
- 知识点按独立学习目标切分。正文应包含必要的对象、条件、符号、推导、结论和图表；不能仅靠邻页或页首整节问题嵌入解释局部变量、题干或“上述结论”。补齐上下文时使用有哈希和范围证据的原文投影，原始题目、问题、概念及来源覆盖不变。
- 知识点文件名使用“规范名称--000001.md”，十进制编号至少六位。YAML 保留稳定 `id`（KID），另存正整数 `knowledge_number` 与学习目标。全局编号由隐藏注册表维护，只追加，不因插入、改名、合并或删除重排、复用；教材来源顺序与数字身份分别保存。
- 已发布知识点的合并、拆分、补齐和改名使用知识专项 `prepare → plan → apply` 审核迁移。审核覆盖全部目标知识身份，记录旧新身份关系、原文范围、逐页独立阅读结果及必要引用更新；保留已校核内容和手工批注，备份后原子应用。普通重导须重放已有审核，不得恢复旧碎片或旧文件名。
- 只导入来源实际提供的问题归类。来源没有则记录 not-in-source，导入0份、目录可空；有具体问题不代表已有思想组织。不得为了填满目录自行生成分类与归属，另行编辑必须有用户明确请求。
- 来源名、source_id、来源文件等放在 YAML 属性，不生成正文来源提示。
- 已有“情境引入与思考”位于标题后、讲解前，按来源顺序用 ![](相对路径.md) 嵌入；以“知识讲解”分隔后续讲解，返回链接保持普通链接，禁止嵌入循环。
- 目录规范.md 和 图片存放规范.md 是本目录的设计依据；索引与规范文件不是知识或习题原子。
- 正式导入只处理用户明确指定的来源，使用已测试的 import_book_graph.py 与哈希绑定的审核清单；不得仅因目录存在就扫描整个高中/。当前来源见索引及隐藏注册表。
- 保留手工内容。迁移或替换前先预览，限定作用域，备份并验证；禁止静默删除。
