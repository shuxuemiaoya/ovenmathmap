# Mathmap 目录约束

遵守父目录的 Vault 数据完整性契约。

## 内容与组织

- Mathmap 有九个内容目录。四组基础目录为习题与题型、知识点与知识串联、问题袋与问题归类、概念或公式与公式总结。
- 四类组织视图负责链接原子并保留各自的来源和体系。`组织层/` 在其上提供书、章和专题的阅读入口。用来源 ID 和章节键匹配已有视图，按入库档案的顺序生成导航，在生成区块外保留导读、授课顺序和章节过渡。
- 原子笔记分别平铺在习题/、习题/解析/、知识点/、问题袋/、概念或公式/。解析是独立原子，题目与解析显式双向关联。
- 每个原子容器拥有自己的 `attachments/` 技术目录；正式图片按内容哈希命名并按前两位分桶，记录原子归属和来源。不预建空桶。
- 题型、知识串联与公式总结保留独立来源、版本和教师体系。问题归类按数学思想、方法策略与思维模型组织，不得用教材章节镜像代替；教材问题顺序另保存在知识串联的来源体系中。同一问题允许多个有依据的归属，均链接同一原子。
- 概念或公式是独立于来源的第四类原子。正文按来源名称分节保存各来源的定义或表述；属性只保留身份和内容信息，不写 source、source_id、source_files、source_node_keys。不生成“引用本原子”“所属组织”等导航，精确出处保留在隐藏入库记录。公式总结只保存来源实际提供的公式或概念总结，禁止按概念归属自动镜像章节；来源没有总结时导入0份且不建来源子目录。知识点保留完整讲解，不自动拆分或迁移。
- 知识点按独立学习目标切分。正文应包含必要的对象、条件、符号、推导、结论和图表；不能仅靠邻页或页首整节问题嵌入解释局部变量、题干或“上述结论”。补齐上下文时使用有哈希和范围证据的原文投影，原始题目、问题、概念及来源覆盖不变。
- 知识点等 K/P/C 原子文件名使用可读内容名，不把编号或稳定 ID 混在名称后。需要类别提示时使用 `知识点-名称.md`、`问题-名称.md`、`概念-名称.md`。YAML 保留稳定 `id`（KID），另存正整数 `knowledge_number` 和 `learning_objective`。全局编号台账保留既有身份的号码，新身份续用 `next_number`，清空资料后继续沿用台账。
- 已发布知识点的合并、拆分、补齐和改名使用知识专项 `prepare → plan → apply` 审核迁移。审核覆盖全部目标知识身份，记录旧新身份关系、原文范围、逐页独立阅读结果及必要引用更新；保留已校核内容和手工批注，备份后原子应用。普通重导须重放已有审核，不得恢复旧碎片或旧文件名。
- 只导入来源实际提供的问题归类。来源没有则记录 not-in-source，导入0份、目录可空；有具体问题不代表已有思想组织。不得为了填满目录自行生成分类与归属，另行编辑必须有用户明确请求。
- 概念或公式的来源与表述写在正文分节，不写入来源属性；其他类型维持来源名、`source_id`、来源文件等 YAML 属性。教学正文、关联导航和校核记录分别成段。网站“知识 Wiki”页签按既有标题隐藏管理段，完整原文可在“来源”及编辑器查阅。
- 已有“情境引入与思考”位于标题后、讲解前，按来源顺序用 `![](相对路径.md)` 嵌入。用“知识讲解”分隔后续讲解，返回链接采用普通链接，避免嵌入循环。

## 导入、清空与恢复

- 正式导入使用 `import_book_graph.py` 和哈希绑定的审核清单，只处理用户指定来源。原子与四类视图通过验收后，预览书章页并核对来源顺序、链接和导读。
- 清空前按来源 ID、文件归属和当前哈希列出范围，验证备份可恢复。只转出该来源独占的文件，保护共享资产、手工内容和结构目录。同步导入注册表、布局来源数、总索引和组织层书目，写入后检查 Git 变更范围。
- 需要恢复原状态时使用经过验证的备份。需要导入新版时重新审核当前来源，并沿用全局编号台账。入库、Wiki 编译和网站发布按各自范围执行。
- 索引与规范属于导航和管理文档。[目录规范](目录规范.md) 说明内容与操作规则，[图片存放规范](图片存放规范.md) 说明原子附件。
