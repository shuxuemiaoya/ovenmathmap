# Mathmap 目录设计

Mathmap 有九个内容目录。原子保存可独立使用的内容，四类组织视图排列原子，`组织层/` 再把这些视图串成书、章和专题的阅读路径。

## 内容目录

| 目录      | 层级       | 存放内容                               | 子目录                          |
| ------- | -------- | ---------------------------------- | ---------------------------- |
| `习题`    | 原子层      | 一道完整习题或例题的题干、来源与解析链接               | 题目平铺；解析平铺于 `解析/`；图片为技术子目录    |
| `题型`    | 习题组织层    | 题型体系、题组、试卷、课后练习、教师选题与训练路径          | 保留体系、版本和原有层级                 |
| `知识点`   | 原子层      | 可复用的概念、定义、性质、定理、公式、方法与完整讲解         | 笔记平铺；允许 `attachments/` 技术子目录 |
| `知识串联`  | 知识组织层    | 教材章节、知识结构、先修关系、教师讲授路线、专题知识体系       | 保留体系、版本和原有层级                 |
| `问题袋`   | 原子层      | 有趣问题、情景导入、探究情境、引出知识的思考与开放问题        | 笔记平铺；允许 `attachments/` 技术子目录 |
| `问题归类`  | 问题组织层    | 数学思想能处理的问题集合、方法策略与思维模型；保留独立教师/编辑体系 | 保留体系、版本和原有层级                 |
| `概念或公式` | 概念原子层    | 单个概念、定义或公式及其必要条件、符号和适用范围           | 笔记平铺；允许 `attachments/` 技术子目录 |
| `公式总结`  | 概念或公式组织层 | 概念清单、公式汇总及其来源顺序、专题和教师整理体系          | 保留体系、版本和原有层级                 |
| `组织层`   | 上层组织     | 书、章、专题的阅读顺序、导读与已有视图入口              | 每本书或体系合并为 1 个 `.md` 文件       |

`题型` 在本设计中是**习题的组织层**，不局限于按题名识别的语义题型。同一概念或题型出现在多个组织体系里是合理复用；不同来源的组织文件不能因名称相似或子项重合被自动合并。

以下是路径示例。题目编号取自全局台账；K/P/C 原子使用内容名。来源缺少某类内容时，对应目录可为空。


解析与题目同属习题原子层；`解析/` 是原子类型分区，不是章节或题型组织。五个原子容器各有 `attachments/` 技术子目录，不新增顶层附件目录。追溯清单和运行状态使用隐藏 `.mathmap-linker/`。完整图片规则见 [图片存放规范](图片存放规范.md)。

## 第四类：概念或公式 / 公式总结

`概念或公式` 保存独立于来源的概念或公式身份，正文按来源名称分节记录各来源的不同定义或表述。属性只保留身份和内容自身的信息，不写 source、source_id、source_files、source_node_keys；不生成“引用本原子”“所属组织”等导航。精确出处与关系存入隐藏入库记录。`知识点` 保留完整讲解；不因讲解中含有公式就自动拆分或复制，既有身份保持原位。

`公式总结` 只保存来源实际提供的公式或概念总结，保留其总结内容、版本及体系。存在概念原子或章节归属，不代表存在总结；禁止自动镜像教材章节。没有真实总结时该来源导入0份，不创建来源子目录。人教A版必修第一册本次来源没有独立总结，公式总结应为空。跨来源的编辑总结需要用户明确请求。

## 原子平铺与身份

- 原子目录不按教材、章节或老师分子文件夹。一本教材和一位老师可以同时使用同一个原子，归属通过组织文件的链接表达。
- “平铺”指原子 Markdown 在各自容器中平铺：`习题/`、`习题/解析/`、`知识点/`、`问题袋/`、`概念或公式/`。它不禁止解析类型分区和图片技术目录。
- 原子身份由稳定 ID 决定，显示标题、文件名、来源路径可以变化。习题优先保留已确认的 QID；知识用 KID，情境问题用 PID，概念或公式用 CID。不同来源的同一原子拥有多条来源记录。
- 语义审核确认重复后，只保留一个共享入口，按来源保存完整表述、适用条件、推导和不同解析。名称相似只是候选信号；文字、数值、条件或符号不同的习题不能直接合并。
- 用有意义的数学对象或条件处理重名；稳定 ID 只放在属性中。标题中必要的数学上下文不能被去重清洗删除，例如椭圆与双曲线的“离心率”。
- 知识点的可见文件名使用内容名称，可加 `知识点-` 文字前缀，不追加编号。内部 KID 保存在 YAML `id`，`knowledge_number` 单独保存数字编号，标题不充当身份。编号只追加、不复用，不因章节重排或改名改变旧号。同名不同义的知识使用不同 KID 与编号。
- “习题”与“问题袋”按教学用途区分，不按难度区分。正式练习、例题和考核题进入习题；动机情境、探究和开放问题进入问题袋。同一内容承担不同用途时，复用一个原子并记录来源角色，不机械复制两份。

原子平铺是物理存储规则，日常浏览以组织目录和搜索为入口。大规模习题不要依靠一个包含全部原子的巨大目录页导航；用各套组织体系、标签与来源索引检索。性能索引可放隐藏状态目录，不能为了归档方便把同一原子按教材复制成多份。

## 组织体系与混合章节

- 四个组织目录都允许不限深度的子目录。每套教材、每个版本、每位老师的体系独立保留；同一老师可以拥有多套不同用途的体系。
- 组织体系使用独立 `system_id`，记录来源、版本、组织者、原章节路径及顺序。体系 ID 不依赖显示名，以便老师改名或教材重排。
- 来源章节的知识、习题与问题顺序均保留出处与原始子项次序，显式互链。教材问题顺序置于知识串联的来源体系；问题归类只保留来源实际提供的思想、方法或模型组织；没有则导入0份，不以章节镜像或自行归纳补充。
- 组织笔记负责顺序、归属和导航，允许跨层引用。不要为了四类视图创建没有内容的占位层级；没有某类子项的章节不生成该视图。
- 组织页默认链接与摘要，不递归展开整本书或全部习题/解析。保留来源的子项顺序；需要展示时只嵌入有限原子，以控制 Obsidian 和网页的单页读取量。
- 混合来源中尚未原子化的完整讲解或情境不能静默丢掉，也不能仅用正则强行切碎。实际导入前应审阅其边界与归属，再形成原子和组织视图。

## 上层组织与阅读顺序

从 [组织层索引](组织层/索引.md) 选书。每本书在 `组织层/` 下合并为单个 Markdown 文件（如 `组织层/人教A-必修第一册.md`、`组织层/北师大-七年级下册.md`），不按章再拆子目录和子文件。书页内按已入库教材档案的顺序分章排列，汇集本章及各小节已有的知识串联、教材问题顺序、题型、问题归类和公式总结。用来源 ID 和章节键对齐视图，仅列入已存在且归属明确的页面。

书页使用普通 Markdown 链接，读者可按需进入知识、问题和练习。导读、授课安排和手工批注写在生成区块外。来源通过导入验收后，运行 Linker 的 `generate_organization_layer.py` 生成预览，核对顺序、链接和手工内容，再合并生成区块。布局元数据的 `organization_layer` 记录上层目录，`content_folders` 记录导入器管理的八个基础目录。

## 知识点的独立阅读与迁移

每篇围绕一个明确学习目标，保留所需的对象、适用条件、局部符号、解释或推导、结论以及配图。允许读者掌握已声明的前置知识，但本页的“该图”“例7的结果”、局部变量与公式编号应在本页有明确依据。字数只用于召回复审，不作为强制切分或合并的目标；完整短性质与方法可以独立保留。

知识讲解可由多个经过审核的原文片段组成，并记录各片段的原文件、范围和哈希。需要从题目、问题或例题取回的必要上下文作为讲解投影，不改变这些原子的内容和身份，也不重复占用原始来源主覆盖。数学 OCR 修订须有原 PDF 或其他明确来源依据，保留校核记录。

知识专项迁移先冻结现状、逐篇审核，再预览名字、编号、身份和引用变更，最后备份并原子应用。合并保留明确存续身份并记录重定向；拆分记录一对多来源关系，不能用单一重定向掩盖。数字编号、来源顺序、内部 KID 分别维护。重复执行和相同来源重导必须保持零变更。

## 原子之间的学习关系

```text
先修知识 ──→ 当前知识点 ──→ 后续知识
                  ↑              
问题袋中的情境 ───┤
推导/证明依据 ────┘
                  │
                  ├──→ 题型/训练组织 ──→ 习题
                  └──→ 对应习题与例题
```

知识点页应能打开先修知识、引入问题、推导依据、后续知识、相关题型和习题，以及使用它的知识串联。习题页能返回对应知识点、相关情境和所属题型/试卷；问题袋中的原子能前往它引出的知识和使用它的问题链。

题目与解析分文件存放，题目链接对应的全部解析，解析以普通返回链接关联题目。每份解析保留独立身份、解法、来源和图片；同一题目可以有多个来源或多种解法。沿用已确认的解析 ID，新解析的 ID 不因列表排序而变化。完全相同的解析可在审核后复用并保留全部出处。来自上游完整例题的题干/解析分离需要审阅边界，不能仅凭“解”等字符串切分。双向关系不得构成互相嵌入的渲染循环。

组织归属、知识依赖和教学动机是不同关系。一个文件排在另一个前面，不足以建立先修关系。关系要保留证据和来源，正向链接与返回链接都显式呈现。来源未提供的关系标为待审阅或不适用，并说明原因。

## Agent 边界与验收

按明确授权整理选定来源，先审核身份、正文区间、组织顺序、图片和学习关系，再只读规划、验收和写入。不得把一本教材的导入扩大到整个高中目录。

导入验收覆盖原子平铺、四类组织视图、书章阅读顺序、题干与解析的双链、附件归属、来源覆盖、身份复用和本地链接。复核手工改动与关联证据，相同来源和审核快照的重复导入应保持零变更。

## 来源清空、恢复与新版导入

1. 从隐藏导入注册表按 `source_id` 确认清空范围。对照归属和当前哈希列出该来源的原子、独占附件、各类视图、书章页及来源档案。遇到共享归属或手工编辑时，先核对引用与归属。
2. 生成只读变更清单，备份将移出或修改的文件，核验哈希并试恢复。应用时逐项复查目标，只清理该来源留下的空子目录。
3. 同步来源登记、布局中的来源数、总索引和组织层书目，核对剩余引用与 Git 变更范围。清空后，九个内容目录、规范、索引和全局编号台账继续用于下一次导入。
4. 恢复原入库状态使用验证过的备份。导入新版先审核新的来源快照、原子身份与章节顺序。既有 KID 沿用已分配的号码，新身份从台账的 `next_number` 续分。来源移出与知识身份停用分别处理。

本地入库、Wiki 编译与网站发布是独立步骤。涉及线上内容时单独核对发布范围及版本。

## 已确定的物理存储规则

1. 解析独立放在 `习题/解析/`，属于原子层。题目与解析通过稳定 ID 和双向链接关联。
2. 图片跟随所属原子容器：`习题/attachments/`、`习题/解析/attachments/`、`知识点/attachments/`、`问题袋/attachments/`、`概念或公式/attachments/`。同一容器共享图片池，用完整内容哈希命名，并按前两位十六进制字符分桶。
3. 原图是可追溯的正式资产。网页缩略图和响应式派生图在发布产物或构建缓存中生成，不把多档尺寸堆进 Obsidian 的原子目录。

已导入来源及数量见索引和各教材的来源与整理说明。原图保留原始字节，网页派生图与 Obsidian 设置属于独立操作。

## 问题归类的内容要求

一个思想分类要说明它能处理什么问题、何时想到它、怎样入手和适用边界；逐项链接具体问题，记录归类理由与原文依据。来源明确提供多个归属时保留这些关联，不复制原子。来源没有该层时记录0份；自行编写分类需要用户另行明确要求。

教材原有的问题顺序保存在各来源的知识串联体系中，可从组织层的书页或章页进入。

## 正文与属性排版

概念或公式页的来源与各自表述写在正文分节，属性不绑定来源，也不追加引用与组织导航；其他类型维持现有来源属性格式。已有“情境引入与思考”放在标题后、讲解前，以 `![](相对路径.md)` 按来源次序分块嵌入，后续内容以“知识讲解”分节。返回链接采用普通链接，避免笔记嵌入循环。

管理导航和校核记录使用独立的二级标题，例如“所属组织”“本节相关知识（范围关联）”“同一章节的其他视图”和“原文校核记录”。把教学内容放在讲解、探究、例题或练习段。网站“知识 Wiki”正文按既有标题隐藏管理段，完整原文与编辑记录可从“来源”查看，关系可从“联系”查看，编辑器和编辑预览使用完整文本。
